# AGENTS.md

## Project: ecash-elements-exchange — Simplicity Exchange on Elements/Liquid

On-chain atomic settlement and automated market making for peer-to-peer asset trading on the Liquid (Elements) sidechain, using Blockstream's Simplicity smart contract language. The project comprises TWO on-chain contracts plus off-chain coordination:

1. **Order Book settlement contract** (`simf/order_book.simf`) — off-chain order matching + on-chain atomic swap settlement (modeled on `simplicity-contracts/.../option_offer.simf`).
2. **AMM / CPMM micro-pool contract** (`simf/amm.simf`) — on-chain constant-product market maker (`K = x * y`), ported from the Cauldron CPMM design (see `docs/REF-CASHSCRIPT-CAULDRON.md`).

The covenant capability set is documented in `docs/RESEARCH.md` (verified from the installed `simc` 0.7.1 jet catalog).

## Key Constraints

1. Simplicity has NO loops or unbounded recursion. Iterating an order book on-chain is impractical.
2. Architecture: Off-chain order matching + On-chain atomic settlement via Simplicity contracts.
3. Each order is a standalone UTXO with its own contract instance.
4. Contract parameters are baked at compile time via `param::` — each order requires a separate compilation.
5. Witness values are provided at spend time via `witness::` and witness files (.wit).
6. SimplicityHL is a work in progress. Not ready for production use.

## Open Questions — ALL RESOLVED (see docs/RESEARCH.md for citations)

1. What covenant jets are available in the current `simc` release for output introspection (asset ID, amount, script, destination of tx outputs)? — RESOLVED: `jet::output_amount(i)`, `jet::output_asset(i)`, `jet::output_script_hash(i)`, `jet::output_is_fee(i)`, `jet::num_outputs()`, `jet::current_index()` all available in the Elements (Liquid) jet environment (`SimplicityHL/src/jet/elements.rs`). Elements-only; absent from Core/Bitcoin.
2. Can a contract verify a specific output sends a specific amount of a specific asset to a specific pubkey? — RESOLVED: asset+amount YES (via `jet::output_amount(i)` + `eq_256`/`eq_64`); destination only via script-hash (`jet::output_script_hash(i)`), NOT a raw pubkey.
3. Is there support for issuing assets programmatically via Simplicity? — RESOLVED: NO. Issuance jets are read-only introspection/calculation; assets must be issued via Elements RPC / PSET issuance fields before contract funding.
4. How does the taker destination address get specified? — RESOLVED: not baked; authorized by the taker's BIP-340 signature over `jet::sig_all_hash()` (free-destination pattern, as in `option_offer.simf` withdraw/expiry paths). Optionally bake a script-hash `param::` for stricter enforcement.

## Development Lifecycle

1. Write `.simf` contract source.
2. Compile: `simc simf/order.simf --json`
3. Inspect: `hal-simplicity simplicity info <base64-program>`
4. Start regtest: `simplex regtest`
5. Build: `simplex build`
6. Run tests: `simplex test`
7. Clean: `simplex clean`
